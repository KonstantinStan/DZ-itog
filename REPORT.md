# Итоговый отчёт: развёртывание и мониторинг audit-svc

## 1. Сборка и публикация образа

Приложение упаковано в Docker-образ и публикуется через GitHub Actions. Для релизного деплоя используется тег версии `v1.0.1`. Развёртывание выполняется на self-hosted runner с помощью Ansible.

Подтверждение: успешный запуск релизного workflow и развёртывание контейнеров на целевом стенде.

## 2. База данных и секреты

- Используется PostgreSQL 17.
- Для хранения данных создан именованный том `audit-postgres-data`.
- База данных называется `audit`, пользователь приложения — `audit_svc`.
- Порт PostgreSQL опубликован только на `127.0.0.1:5433`.
- Секреты хранятся в зашифрованном Ansible Vault-файле `deploy/inventories/prom/group_vars/all/vault.yml`.
- Пароль Vault передаётся через секрет GitHub Environment `ANSIBLE_VAULT_PASSWORD`.

## 3. Деплой и идемпотентность

Релизный деплой выполняется через Ansible. Конфигурация приложения формируется из шаблона и устанавливается с правами `0640`. При изменении конфигурации предусмотрен handler для её перечитывания без перезапуска контейнера приложения.

Повторный запуск playbook завершился успешно:

- `ok=14`
- `changed=0`
- `unreachable=0`
- `failed=0`
- `skipped=1`

Таким образом, повторный запуск на текущем состоянии стенда не внёс изменений.

Проверка ротации пароля с подтверждением неизменности `StartedAt`, сообщения о переподключении к БД и роста `audit_config_reloads_total` в этот отчёт пока не включена: отдельные доказательства этой процедуры не зафиксированы.

## 4. Nginx и nginx-exporter

Nginx принимает запросы на порту `8088`. Прямой порт приложения `8080` не опубликован на хосте. PostgreSQL доступен с хоста только через loopback на порту `5433`. Метрики экспортера доступны на порту `9113`.

Проверка обходных вариантов пути к обработчику `/reload` через Nginx дала следующие результаты:

| Запрос | HTTP-код |
|---|---:|
| `/reload` | 404 |
| `/reload?x=1` | 404 |
| `//reload` | 404 |
| `/%72eload` | 404 |

Метрика `nginx_up` имеет значение `1`, что подтверждает доступность Nginx для экспортера.

Результаты проверок сохранены в `screenshots/checks.txt`.

## 5. Prometheus и Grafana

Prometheus успешно опрашивает обе цели мониторинга:

| Job | Статус | Endpoint |
|---|---|---|
| `audit-svc` | UP | `http://nginx:8088/metrics` |
| `nginx` | UP | `http://nginx-exporter:9113/metrics` |

Конфигурации дашбордов находятся в репозитории:

- `monitoring/grafana/audit-svc.json`
- `monitoring/grafana/nginx.json`

Генератор нагрузки запускался на 600 секунд. По итогам выполнения зарегистрировано 2985 ответов:
- HTTP 200 — 289;
- HTTP 201 — 2546;
- HTTP 400 — 150.

## 6. Дополнительное задание: миграции

Playbook запускает миграции базы данных до обновления контейнера приложения. Отдельный релиз с миграцией `0003_*.sql` и подтверждающий лог в рамках описанных проверок не зафиксированы.
Миграция 0003_events_received_at_index успешно применена и наличие всех трёх миграций подтверждено запросом к базе audit.
